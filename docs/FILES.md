# Every file in this project

A guided index of the repository. If you are looking for *how the pieces fit
together* rather than *what each file is*, read [ARCHITECTURE.md](ARCHITECTURE.md)
first.

## Top level

| File | What it is |
| --- | --- |
| `README.md` | The user-facing documentation: quick start, the endpoint table, what the OData layer supports, how to simulate failures, how to extend the mock. |
| `LICENSE` | MIT, verbatim, so GitHub and `licensee` detect it. The SAP trademark disclaimer deliberately lives in the README instead - appending anything to the licence text breaks that detection. |
| `pyproject.toml` | Packaging metadata and the **single source of truth for the version**. Declares the `mock-sap` console script and, notably, zero dependencies. |
| `CHANGELOG.md` | Every release, what it added and what it fixed, in Keep a Changelog form with links to the compare views. |
| `CONTRIBUTING.md` | What the project values and how to work on it: the principles that decide what gets merged, where to add each kind of thing, what a good pull request carries, and the release process. |
| `SECURITY.md` | What counts as a vulnerability in a test double and what does not, and how to report one privately. The distinction is the point: no authentication by default, no TLS and a reachable `POST /_mock/reset` are deliberate, while anything that escapes the mock's own state - reading files outside its database, running what a request supplies, or a published artifact that does not match the tagged source - is in scope. |
| `MANIFEST.in` | Adds the Dockerfile, examples and the test modules to the sdist; without it an sdist carries only the package itself. `tests` by `*.py`, so the vendored CSDL schemas under `tests/samples/` are deliberately not shipped: nothing in `tests/` reads them, only `tools/`, which is not packaged either. |
| `Dockerfile` | `python:3.12-slim`, `pip install .`, entrypoint bound to `0.0.0.0:8000`. Built and exercised by CI on every push. |
| `.gitignore` | Build output, virtualenvs, `*.db` files left behind by `--db`. |
| `.gitattributes` | `tests/samples/external/** -text`: the vendored CSDL schemas keep the bytes OASIS and Microsoft published. `tools/check_csdl.py` checks each one's SHA-256 before it uses it, and without this a Windows checkout rewrites every LF to CRLF and every one of those hashes stops matching. mock-bank learnt this the same way, on `windows-latest` alone. |
| `changelog.d/` | One file per changelog entry waiting for a release, named `<issue>.<kind>.md`, holding the bullet exactly as it will appear. A directory of small files instead of one shared section, because two pull requests editing the same lines of `CHANGELOG.md` conflicted every time, a conflicting pull request gets no CI run at all, and a resolution by hand is one keystroke from dropping an entry — which is how the V2 annotation document's entry went missing between 0.8.0 and 0.9.0. Documented as a directory: a row per fragment would put every pull request back to editing one shared file. `README.md` there has the format. |
| `.github/dependabot.yml` | Weekly `github-actions` updates, grouped into one pull request and labelled `no changelog`. The package has no dependencies, so Actions are the whole surface; this is also what keeps the commit SHA that `publish.yml` pins from going stale, which is the thing that makes pinning stick. |

## `mocksap/` - the package

Roughly in dependency order: `schema` sits at the bottom and depends on nothing,
`server` sits at the top and depends on everything.

| File | What it is | Edit it when |
| --- | --- | --- |
| `schema.py` | The declarative heart. `Prop`, `ComplexType`, `Nav`, `EntityType`, `UI` and `Service` definitions for the entity types the mock serves - the S/4HANA `API_*` shapes and the classic `GWSAMPLE_BASIC` demo service. Tables, `$metadata`, payload shapes and key handling are all derived from here. | Adding or changing an entity set, property or navigation. |
| `clock.py` | System time: one clock every date is computed against, pinned with `--clock` and moved with `POST /_mock/advance`. Holds an offset rather than an instant, so it keeps ticking between advances and two rows written a moment apart still sort in the order they were written. Naive UTC only, and it knows nothing about business days - no cutoff, no weekend, no holidays. |
| `db.py` | SQLite: DDL generated from the schema, number-range objects (`next_number`), the deterministic seed data, and the `request_log`, `idoc`, `idoc_statement`, `idoc_statement_line`, `idoc_delivery`, `idoc_invoice`, `bank_statement` and `rfc_log` tables. A new table is added with `IF NOT EXISTS`, so a database written by an earlier version picks it up on open; a new *column* on an existing table would not, which is why every posting outcome is its own table rather than a column. | Changing demo data, or adding a non-entity table. |
| `odata4.py` | The V4 shapes: `@odata.context`/`@odata.count`/`@odata.etag` annotations, ISO 8601 timestamps, decimals as numbers, the V4 error object and service document. Everything below the wire is shared with V2. |
| `apply.py` | The `$apply` pipeline: parsed into a plan of filter, grouping keys, aggregates, ordering and paging, and handed to SQLite as one `GROUP BY` statement. Refuses transformations it does not implement by name. |
| `delta.py` | Delta tokens: minting and reading them, finding a type's change timestamp, and reading back the deletions that would otherwise leave no trace. |
| `metadata4.py` | CSDL 4.0, in XML and in JSON, including the UI and Capabilities annotations and the vocabulary references that make them resolve. No Association elements - V4 navigation properties carry their target type, and the container binds them to entity sets. |
| `odata.py` | The OData V2 vocabulary: the `$filter` tokenizer and recursive-descent parser that compiles to parameterised SQL, key-predicate parsing and rendering, EDM ↔ JSON value conversion, the response envelopes, the SAP error payload, and `check_writable`, which holds a write to the `sap:creatable`/`sap:updatable` facets the metadata is rendered from. | Adding a `$filter` function, a new EDM type, or changing how values are rendered. |
| `annotations.py` | The V2 annotation document: the same `EntityType.ui` intent the V4 services render inside `$metadata`, in the separate document a V2 app fetches. Only a service that opts in publishes one. |
| `metadata.py` | Generates the EDMX `$metadata` document (entity types, associations, referential constraints, `sap:` annotations, the entity container) and the Atom/JSON service documents. | Changing what `$metadata` advertises. |
| `store.py` | CRUD over SQLite: query, deep insert, update with MERGE-vs-PUT semantics, cascading delete that records what it removed, auto-assigned document numbers, item numbering, total recalculation, ABAP initial values, and the monotonic change timestamp the ETag is derived from. | Changing write behaviour or the system-filled fields. |
| `service.py` | The OData request dispatcher, shared by both dialects: URL segmentation, query-option handling, `$links`/`$ref`, and the `Response`/`Context` types. A POST to `A_SupplierInvoice` is routed to `documents` rather than to `store`, so an invoice created over OData is the same document as one posted from an inbound IDoc. Deliberately transport agnostic - `dispatch()` is called both by the HTTP server and by `$batch`. | Adding a URL shape or a query option. |
| `batch.py` | `$batch` in both dialects: multipart/mixed with changesets for V2, JSON with atomicity groups for V4, and the snapshot that makes either roll back as a unit. | Changing batch semantics. |
| `bapi.py` | The RFC layer: the function-module registry, the BAPIRET2 helper, the seventeen implemented function modules - including `BAPI_SALESORDER_CHANGE` with its X structures and `RFC_READ_TABLE` with its own guarded OPTIONS parser - and the SOAP transport (envelope parsing, response rendering, faults). | Adding a BAPI or changing RFC error shapes. |
| `bank.py` | Bank details a payment run can use: the ISO 13616 check-digit test that refuses a mistyped IBAN when it is entered rather than days later at the bank, which countries are on IBAN at all, and the valid IBANs the seed builds so the mock's own data passes the check it applies to clients. |
| `reconcile.py` | Matching a bank statement to the open items it pays: clearing on reference and amount, posting one payment document per supplier rather than per line (which clears its own supplier lines, so a payment is not a new debt), reopening an item when a payment is returned, ours or a customer's, clearing the receivable a customer's credit quotes with one receipt document per customer and or the set of several that sums to it, refusing a part payment or an ambiguous set rather than posting one, clearing an invoice paid net of the discount its terms offer and leaving an unearned discount open, and reporting every line it could not place rather than guessing. Also the statement's own arithmetic and whether it follows the last one, and `settlement_of`, which reads back what one payment settled - through `ClearingItem`, so a row's amount is what the payment paid rather than what the invoice was for - as the facts a remittance advice is built from. What it decided is filed by `outcome.py`, not here. | Another way of matching a line to an item. |
| `outcome.py` | What posting an IDoc decided, filed under the IDoc it arrived on and read back by `GET /sap/bc/idoc/<DOCNUM>`: a statement's lines, the sales orders a delivery moved, the invoice and payable a bill posted. One small table per shape rather than one table with a `kind` column, and no table stores the sentence it answers with - every `MESSAGE` is rebuilt from the numbers beside it, so the receipt's wording and a later read's cannot drift apart. That is why a delivery outcome stores the position a `DELVRY` named and could not find, rather than the sentence about it. | A fourth message type starts posting something. |
| `statement.py` | Reading an inbound `FINSTA01` bank statement: the account, the number and date, the balances by SAP's own `EDIF5025` qualifiers, and each line's reference, note to payee and amounts, as `Decimal`. Which side a line is on is the mock's convention - the amount's sign - because SAP pins none, and so is which kind of credit it is - `LINACTION` `RET` or `RCV`, a payment coming back or money arriving - for the same reason, with `RET` on a debit for money we received going back. Also the check that a statement adds up on its own. Acting on a statement is not here. | Reading another FINSTA01 segment. |
| `documents.py` | Creating the documents a sales order turns into - a delivery, an invoice and the journal entry it posts - and moving the order's delivery status. Three layers need these (the BAPIs, the IDoc generators, an inbound delivery) and a document must look the same whichever created it. Also the payment terms a line is given: `PAYMENT_TERMS` in miniature, the net due date that follows from it, and the cash discount a key can offer - what a payment on a given day earned of it, which only the terms can say. |
| `money.py` | Amounts as `decimal.Decimal`: reading one in from whatever a client sent, rounding to a scale with `ROUND_HALF_UP` because that is what SAP and a tax authority do, and the canonical text an `Edm.Decimal` column holds. One module so the convention is in one place; the reason it exists is in its docstring. | Changing how an amount is rounded or stored. |
| `idoc.py` | IDoc inbox and outbox: XML and EDI_DC40 flat-file parsing, status records, ORDERS05/INVOIC02/DELVRY07 generation from a stored sales order, a PEXR2002 remittance advice from a payment document instead (so `generate` asks `source_of` what a message type reads rather than assuming an order), and the posting of an inbound delivery against the order it references. The by-docnum read also returns what posting a `FINSTA01` decided, and the listing takes `settled` to find it from the invoice's side. | Adding an IDoc type or segment. |
| `messages.py` | The `sap-message` warnings: how they are rendered into the header, and the small set of rules that produce them from the data (a delivery date in the past, a blocked customer, a material flagged for deletion). |
| `oauth.py` | The mock authorization server: the token store, the grants (client credentials, password, SAML bearer, refresh), bearer validation and revocation. Opaque tokens held in memory - there is no cryptography here, by design. |
| `server.py` | The HTTP front end: routing, CSRF tokens, basic auth, `sap-client` validation, latency and fault injection, the request log, the `/_mock` control plane and the human-readable index page. | Adding an endpoint, a failure scenario or a cross-cutting header. |
| `__init__.py` | Re-exports `Config` and `make_server`, and derives `__version__` from the installed package metadata (falling back to `pyproject.toml` in a source checkout, where it reports `…+source`). | Rarely. |
| `__main__.py` | The `mock-sap` / `python -m mocksap` command line: argument parsing and the startup banner. | Adding a CLI flag. |

## `tests/` - one module per surface

with `python3 -m unittest discover -s tests -v`, or a single surface with
`python3 tests/test_batch.py`.

### `tests/samples/external/csdl/` - schemas this project did not write

Five files from outside the project, byte-for-byte as published, and the
paperwork that comes with them. They are what `tools/check_csdl.py` holds the
served `$metadata` to, and the reason they exist is #78: everything else that
checks this mock's output checks it against `mocksap/schema.py`, which is also
what wrote it. `SOURCES.md` beside them has the full provenance.

| File | What it is |
| --- | --- |
| `tests/samples/external/csdl/edmx.xsd`, `tests/samples/external/csdl/edm.xsd` | OASIS's two schemas for CSDL XML 4.01, from the OASIS Standard of 11 May 2020. They validate the four V4 services' `$metadata` and the V2 annotation document, which is a CSDL 4.01 envelope too. |
| `tests/samples/external/csdl/System.Data.Resources.CSDLSchema_2.xsd` | Microsoft's schema for `http://schemas.microsoft.com/ado/2008/09/edm`, the namespace an OData V2 `<Schema>` is in, from Entity Framework 6 at `v6.5.2`. It validates the `<Schema>` subtree of each V2 service; the EDMX envelope above it has no published schema, so `check_csdl.py` asserts that part itself and says so. |
| `tests/samples/external/csdl/System.Data.Resources.CodeGenerationSchema.xsd`, `tests/samples/external/csdl/System.Data.Resources.AnnotationSchema.xsd` | The two schemas `CSDLSchema_2.xsd` imports by name from its own directory. Without them it does not compile, and a schema that does not compile is how a check quietly becomes a no-op - which is why the filenames are the published ones. |
| `tests/samples/external/csdl/SOURCES.md` | Where each schema came from, the release or commit, its licence, its SHA-256, what it covers - and what it does not: the `sap:` annotations, which both schemas admit as foreign attributes and read past unexamined, and the V2 EDMX envelope. |
| `tests/samples/external/csdl/NOTICE-oasis-odata.txt`, `tests/samples/external/csdl/LICENSE-MIT-ef6.txt` | The notice OASIS asks for, and Entity Framework 6's MIT licence, kept beside the files as that licence asks. |

## `tools/`

| File | What it is |
| --- | --- |
| `check_changelog.py` | Guards `CHANGELOG.md` and `changelog.d/`. Structure and agreement with `pyproject.toml` always; that `## [Unreleased]` holds the pointer and no entries; that every fragment is named `<issue>.<kind>.md` for a kind Keep a Changelog defines and holds a real bullet; that every `[#nn]` the file references is defined; and, against a base revision, that released sections are untouched, that nothing waiting for a release has gone, and that a change to `mocksap/` brought an entry with it — which is what a merge resolution that drops one side trips over. A pull request labelled `no changelog` lifts that last rule. `--release X.Y.Z` assembles the fragments into a dated section, writes the link definitions and deletes them, and opens the section with a table of the projects that install this one - built from `CONSUMERS` - whose last column it writes as a placeholder the checks refuse, so that whether a release was run against its consumers is typed rather than left out. Came back from mock-edi, which grew the fragment directory after this check was first written here. |
| `check_csdl.py` | The one check on this mock's output that is not a check against its own declaration (#78). It validates every `$metadata` the mock serves, and the V2 annotation document, against schemas OASIS and Microsoft published and this project vendored unmodified under `tests/samples/external/csdl/`: whole-document for the V4 ones, the `<Schema>` subtree for the V2 ones, because no published schema covers OData V2's EDMX envelope and that part is asserted here in Python instead of dressed up as a schema. Two things an XSD cannot do, it does itself: it reads the primitive type names out of those same schemas and holds every `Type=` to them, since CSDL spells a type reference as a loose pattern and `Edm.Str` validates happily; and it breaks one document of each kind in twelve ways the spec forbids and fails if any is accepted, so the check cannot become a no-op. Needs `xmllint`; without it the validation is skipped and says so, and `--require` turns that skip into a failure, which is how CI runs it. |
| `check_docs.py` | Guards this index against drift: fails if a tracked file is not documented here, if a row names a file that no longer exists, or if a module is missing from the README's layout block. It checks coverage, not prose. It also holds every module to running whole as a script, since `python3 tests/test_batch.py` is the documented way to run one surface: nothing may follow an `if __name__` block (a class below `unittest.main()` never runs, and the run still says OK), and a test module imports `support` before `mocksap`. Run it with `python3 tools/check_docs.py`; CI runs it on every push. |

## `.github/workflows/`

| File | What it is |
| --- | --- |
| `ci.yml` | Seven jobs: the suite on Python 3.8-3.13 (Linux) plus 3.12 on macOS and Windows; a docs job running `tools/check_docs.py` and `tools/check_changelog.py`; a `csdl` job that installs `libxml2-utils` - the runner image does not carry `xmllint`, and `--require` is what made that a failure instead of a silent skip - and runs `tools/check_csdl.py --require`, which is its own job so that a schema failure names itself rather than arriving as a confusing test error; a smoke job running `demo.sh` and `client.py` against a live mock; a package job that builds, `twine check`s, installs the wheel and asserts the version agrees with `pyproject.toml`; a job that builds and runs the Docker image; and an `all green` job that fails unless every one of the others succeeded. That last one exists to be the single required check on `main` - the matrix job names carry the Python version and the runner, so they change whenever the matrix does, and a required check whose name has gone blocks every merge rather than failing. |
| `publish.yml` | Releases to PyPI via Trusted Publishing (OIDC, no stored token). A published GitHub Release goes to PyPI; a manual run goes to TestPyPI. Both build from a green test run and refuse a tag that disagrees with the built package. |
